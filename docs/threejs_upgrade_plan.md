# Three.js 升级计划 (v0.118 to v0.181)

## 1. 概述

当前项目使用的 Three.js 版本为 `0.118`，而最新的稳定版本为 `0.181`。这是一个包含超过 60 个版本的巨大跨越，其中包含了大量重大变更（Breaking Changes）。直接升级是不可行的，并且会严重破坏项目的功能和视觉效果。

**核心挑战**:
*   **API 变更**: 许多核心 API、材质属性和几何体管理方式已被废弃或重构。
*   **颜色管理**: Three.js 的颜色管理系统已完全重做，以实现更物理精确的渲染，这会直接影响最终的视觉效果。
*   **加载器**: 旧的加载器路径和 API 已被更改，特别是项目依赖的 `ColladaLoader`。
*   **代码组织**: 库已完全转向 ES6 模块，所有导入路径都需要更新。

## 2. 升级策略：增量升级

官方建议以 10 个版本为单位进行增量升级。这是一个稳妥但耗时巨大的过程。一个更现实的策略是分阶段进行，每个阶段都解决一类核心的重大变更。

## 3. 分阶段升级计划

### 阶段一：准备工作与版本跳跃 (升级到 r125)

**目标**: 完成向 `BufferGeometry` 的完全过渡，并解决 r125 之前最主要的 API 变更。r125 是一个关键版本，因为它完全移除了旧的 `Geometry` 类。

1.  **更新依赖**: 在 `package.json` 中将 `three` 的版本更新到 `~0.125.0`。
2.  **检查 `Geometry`**: 全局搜索代码库，查找任何 `THREE.Geometry` 的使用实例（例如，访问 `geometry.vertices` 或 `geometry.faces`）。将所有这些实例重构为使用 `THREE.BufferGeometry`。
3.  **更新加载器路径**: 查找所有从 `three/examples/jsm/` 导入的模块（如 `OrbitControls`），并根据 r125 的文档更新它们的导入路径。
4.  **测试与修复**: 运行所有示例页面，修复因 API 变更导致的明显错误。此时视觉效果（特别是颜色）可能仍然是错误的。

### 阶段二：颜色管理与材质迁移 (升级到 r150)

**目标**: 解决最复杂的颜色管理问题，使渲染效果符合现代 Three.js 的标准。

1.  **更新依赖**: 将 `three` 的版本更新到 `~0.150.0`。
2.  **颜色空间迁移**:
    *   在 `Viewer.js` 中，将 `renderer.outputEncoding = THREE.sRGBEncoding;` 修改为 `renderer.outputColorSpace = THREE.SRGBColorSpace;`。
    *   检查所有 `Texture` 的 `encoding` 属性，并将其更新为新的 `colorSpace` 属性。
3.  **材质更新**:
    *   全局审查 `MeshStandardMaterial` 和其他材质的使用。根据 r150 的文档，更新所有被废弃或重命名的属性（例如 `transmission`）。
    *   检查 `vertexColors` 的使用方式是否正确。
4.  **光照调整**: 由于颜色和材质的变化，可能需要重新调整场景中的光照强度和颜色，以匹配原始的视觉感受。
5.  **测试与修复**: 重点测试所有模型的颜色、光泽度和透明度是否正确。

### 阶段三：最终 API 对齐与加载器重构 (升级到 r181 - 最新版)

**目标**: 完成剩余的 API 升级，并确保所有外部模型能正确加载。

1.  **更新依赖**: 将 `three` 的版本更新到最新版（`^0.181.0`）。
2.  **`ColladaLoader` 检查**:
    *   确认 `ColladaLoader` 在最新版中的状态。它可能已被移至 `three/examples/jsm/deprecated/` 或完全移除。
    *   如果加载器仍然可用，更新其导入路径和 API。
    *   **风险**: 如果 `ColladaLoader` 已被移除，这是一个重大障碍。备用方案是：
        *   寻找社区维护的 `ColladaLoader` 分支。
        *   在项目中保留一个旧版本的 `ColladaLoader` 文件。
        *   （推荐）将示例资源从 `.dae` 格式转换为 `glTF` 或 `glb` 格式，并使用 `GLTFLoader`。这将是一项额外的工作，但 `glTF` 是现代 Web 3D 的标准。
3.  **最终 API 清理**: 运行项目并检查浏览器控制台。Three.js 会输出所有剩余的弃用警告。根据警告，逐一修复所有过时的 API 调用。
4.  **全面回归测试**: 对所有示例页面进行全面的功能和视觉测试，确保一切正常。

## 4. 成本与风险评估

*   **时间成本**: **巨大**。这是一个涉及全方位代码修改的大型重构任务，可能需要数天甚至数周的工作量，具体取决于期间发现的未知问题。
*   **风险**:
    *   **视觉一致性**: 最大的风险是无法 100% 还原原始的渲染效果，尤其是在颜色和光照方面。需要进行大量的人工调整和对比。
    *   **依赖项破坏**: `ColladaLoader` 的状态是最大的技术风险。如果它不再受支持，加载 URDF 网格资源的功能将中断，需要投入额外精力解决。
    *   **未知问题**: 在 60 多个版本中，可能存在未在迁移指南中明确强调的细微变更，这些变更只有在测试时才能发现。

**结论**: 升级是技术上的必然选择，可以带来性能提升和对现代功能的支持。但考虑到巨大的工作量和风险，建议将其作为一个独立的、资源充足的大型任务来规划，而不是在当前阶段立即执行。
